## Requirement-derived test plan

- **AC8a.1 — retained complete batches:** Exercise accepted direct-resource and sync publication through real HTTP. Independently construct expected canonical changes for custom exercise, draft/saved routine, active/finished workout and deletes. Assert rich ordered children, null/zero/rest values, IDs/revisions, batch/change envelope agreement, stored historical payload/labels after rename/replacement/deletion, and indivisible old-active DELETE then new-active UPSERT. Exclude bundled and foreign data.
- **AC8a.2 — pagination/boundaries:** Cover empty account and nonempty pulls at limit 1/default/200, over 200 batches, exact/partial terminal pages, traversal without gaps/duplicates, valid push-cursor continuation, preserved empty-tail boundary, concurrent null starts and another live same-account session. Assert `hasMore` implies progress and each `nextCursor` covers only returned batches. Snapshot all protected/sync/replay/credential state around metadata-only token registration and assert no other change.
- **AC8a.3 — retained start/failures:** In isolated DB test fixtures only, atomically remove a complete committed prefix and set its watermark. Verify before-watermark known token gives 410 `cursor_expired` plus `fullResyncRequired:true`, equality/after usable, absent cursor starts at retained-start including all-pruned empty history, and unknown/foreign/malformed/empty tokens remain 400 `invalid_cursor` even against pruned history. Verify old valid unchanged boundaries do not expire by age. Fixture manipulation is not evidence of production pruning.
- **AC8a.4 — auth/validation/state safety:** Verify missing/invalid/expired/revoked bearer and disabled account fail with `401 authentication_required`; another current same-account session succeeds. Verify query allowlist, duplicate scalar parameters, ASCII integer syntax/range/defaults, opaque cursor handling, GET body absent/zero vs nonempty 422, optional Idempotency-Key has no replay semantics, and safe error envelopes. Snapshot protected data around success/errors/retries; allow only boundary-token registration.
- **AC8a.5 — consistency/durability/fault safety:** Use deterministic PostgreSQL/HTTP gates to prove allocated-but-uncommitted work cannot be skipped and a multi-change publication is not partially visible (a complete pre-write view is valid). Review actual transaction/isolation participation. Restart the service/process and pull using persisted cursors/historical data. Inject test-owned transient/unexpected read-path faults to assert safe 503/500 and successful unchanged retry after removing the fault; responses expose no SQL/private diagnostics and failures persist no durable outcomes.
- **AC8a.6 — maintainability:** QA records observations/questions for Coordinator's structural review; acceptance remains Coordinator-owned. Test seams/findings are routed through Coordinator, not addressed by production edits.
- **AC8a.7 — frozen verification:** After authoring, report test-source stability and request an agreed frozen-input slot for pull plus existing push/preflight/direct mutation/read/browse/auth regression coverage and full suite. Preserve exact commands, fresh Surefire totals/failures/errors/skips, copied reports, and before/after relevant manifests. No verification run before slot approval.
