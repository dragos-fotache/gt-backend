## Common committed-boundary protocol

- Every account has a valid opaque zero-commit boundary. Tokens bind account and internal committed boundary, not login session, token age, lexical order, revision or list-page context. Previously issued push cursors must remain compatible across restart and later slices.
- Cursor validity is about missing subsequent history: boundary below durable `pruned_through` expires; equality remains usable. Unknown/foreign/malformed tokens are invalid, never initial cursors. No age-based cursor expiry.
- At service time T, eligible pruning is batches committed at or before T minus 90 elapsed days. Prune only the contiguous oldest committed prefix, stopping at the first ineligible batch even if later batch timestamps are older after clock correction. Advance pruning metadata atomically with deletion. Preserve account-lifetime replay and identity metadata.
- Readers may not advance beyond allocated-but-uncommitted work or skip required contiguous batches. View of authorization, account sync state, batch metadata and ordered changes must be transactionally coherent. A read may return a fully committed pre-write view, not a hybrid.
- Historical upserts replay their stored canonical payloads and convenience labels; never re-materialize them from current domain rows. Deletes carry their stored positive revision and no live record. No bundled catalogue changes or private ownership/credential/internal SQL leakage.

## 8a — incremental pull and shared cursors (accepted)

`GET /v1/sync/pull` returns `200 {batches, nextCursor, hasMore}`. A batch has canonical batchId, nonempty cursor and a nonempty ordered changes array. Changes are complete canonical upsert/delete records matching type/ID/revision. Whole batches and aggregates are indivisible; no byte-based truncation or new product caps.

- Allowed query parameters are scalar `cursor` and `limit`, each at most once. Absent cursor starts at retained-start (`pruned_through`), not a full bootstrap. Explicit empty or malformed/unknown/foreign cursor is `400 invalid_cursor`.
- Limit is complete batches, 1–200, default 100. Omitted/explicit default agree. Unknown parameters, duplicate scalars and malformed/out-of-range/noninteger limit are `400 invalid_request`. Supported numeric syntax is ASCII decimal digits without sign/whitespace. A supplied cursor is opaque; no trimming or silent initial fallback.
- GET body must be absent/zero bytes; nonempty body is `422 validation_error`. Optional Idempotency-Key has no read/replay semantics. No cross-invalidity precedence beyond the distinct token failure rules is promised.
- Require a current live service bearer credential. Missing/invalid/expired/revoked access or disabled account returns `401 authentication_required`; token possession alone never authorizes. Another live same-account session may use its account's cursor. New reads after logout/disablement reject.
- Return complete batches strictly after the supplied/retained-start boundary in internal committed order, preserving change position. `nextCursor` covers only batches actually returned. Empty page preserves supplied valid boundary or retained-start for absent input; its cursor remains nonempty. `hasMore=true` requires a nonempty advancing page. Exact terminal pages have hasMore false, not a full-page heuristic.
- Known valid boundary below pruning watermark returns `410 {errorCode:"cursor_expired", fullResyncRequired:true}`. Equality remains usable, including empty retained history. Timestamp/token age alone never expires a cursor. 8a uses controlled test-only pruned fixtures, not a production pruning implementation.
- Shared cursor issuance/resolution may persist missing boundary-token metadata (particularly zero/retained-start), using the existing opaque token registry. This is the only expected GET metadata effect. It must be concurrency-safe, stable and not modify domain, revisions, timestamps, reservations, committed/pruned boundaries, batches, replay evidence, credential expiry or list-token semantics. Preserve existing published push and direct-resource behavior and replay bytes. A narrowly bounded extraction of cursor handling from the publisher is allowed, not a redesign of mutation execution.
- Errors are safe contractual envelopes. Transient database failures return 503 temporarily_unavailable; unexpected failures return 500 internal_error. Do not report corrupt/missing required history as successful progress, an empty complete page or invalid user input. No durable mutation outcome from failed reads.
