## Test design principles

- Add cohesive dedicated snapshot HTTP/PostgreSQL integration coverage and fixtures; do not use the production mapper, response body, snapshot storage, or implementation-derived helper as the expected-value oracle. Independently construct expected canonical JSON/records from accepted writes and the specified wire/domain rules.
- Prefer actual mutation HTTP surfaces to create input state, then call `GET /v1/sync/snapshot` over real HTTP. Use deterministic database gates/latches for concurrency, not timing sleeps or service simulators. Test-only direct SQL is for controlled setup/fault injection and state inspection, not substitute route evidence.
- Assert full records and envelope consistency (type, UUID, operation, positive revision, canonical `record`), null versus zero/empty distinctions, order, baseline, token behavior, and protected-state non-mutation. Do not weaken or replace assertions in accepted tests.
- Keep auth shared-path supplements, actual snapshot-route evidence, direct database checks, scheduler invocation, and real-process restart evidence explicitly distinguished in reporting. Findings or required seams go to Coordinator; no production edits.

## Requirement-first coverage plan

### AC8c.1 — complete canonical bootstrap

Create custom exercises, routines (empty draft, populated draft, saved routine including legitimate blank/empty autosave), and active/finished workouts through accepted mutation APIs. Build expected canonical records independently, including ordered children/IDs, nullable versus zero values, configured and recorded rest, notes, completion/time fields, metadata and custom-exercise convenience labels. Verify all live roots are included even when unchanged and older than retained change history; include a large aggregate and references/dependencies. Use controlled isolated DB state for catalogue, tombstone, foreign-account and other-account exclusions, with explicit API assertions that no private/foreign root leaks. Assert no revision fan-out for label-only effects and that every record's envelope matches its canonical payload. Keep shared-auth checks supplementary to route evidence.

### AC8c.2 — type/UUID order, record limits and replay

Cover empty account; effective limits 1, omitted/explicit default 200, and 500; more than 500 roots across types; exact and partial terminal pages; repeated traversal with no duplicates, omissions or split records; and a large aggregate proving limit counts records, not bytes/children. Include the same UUID in distinct root-type namespaces and UUIDs spanning the signed/high-bit boundary. Derive expected order as customExercise, routine, workout, then lowercase canonical UUID string ascending. Verify equivalent numeric spellings and omitted/explicit default context, same valid continuation replay returning byte/value-identical records, baseline, `hasMore` and next token. Verify separate null-token starts are independent without asserting initial-request replay/idempotency.

### AC8c.3 — frozen contents, writes and baseline-to-pull continuity

Capture multiple pages, then use real HTTP to rename/edit/delete/create roots and replace the active workout. Remaining pages and token replays must preserve original records/labels and one baseline; pull from that baseline must expose later complete committed batches. Use deterministic real PostgreSQL transaction gates around allocated-but-uncommitted publication and multi-root publication; accept a complete pre-write or post-write view only, and prove later committed work is pull-visible from the snapshot baseline. Exercise snapshot capture against production pruning and continuation against expired cleanup, checking coherent complete pages and no normal-race hybrid/missing-data failure. No timing sleeps. Review transaction participation separately from route tests.

### AC8c.4 — live authentication, request and token validation

Through the snapshot route, cover missing, invalid, expired and revoked access, disabled account, a second live same-account session continuing a token, and foreign-account isolation. Validate absent initial token versus explicitly empty token; malformed/tampered/unknown/wrong-surface/foreign/context-mismatched tokens; changed effective limit including omitted-on-continuation semantics; duplicate and unknown parameters; non-ASCII/non-digit, empty, signed, whitespace, fraction/exponent, overflow and out-of-range limits; and nonempty GET body. Verify safe error codes/envelopes and no token, payload, credentials, IDs, SQL or stack traces in exposed errors. Correctly-bound expired tokens must remain `410 snapshot_expired`; foreign/changed-limit expired tokens must remain `400 invalid_snapshot_token`. Assert no invalid request silently starts a snapshot. Keep generic auth tests separate from snapshot-route assertions.

### AC8c.5 — exact access expiry and bounded physical cleanup

Use the controlled service Clock to test just before 86,400 seconds, exactly at expiry, and after; prove replay/capture/page access does not slide expiry. Distinguish `410` logical expiry from physical payload deletion. After expired-storage cleanup, authentic correctly bound tokens remain `410`, including after restart; no expired-data access is restored. Verify finite work budget, multi-tick backlog progress, preservation of unexpired and unrelated-account state, actual Spring scheduler invocation, fixed sanitized failure logging and recovery, rollback/retry, and concurrent cleanup safety. Record that scheduled backlog/downtime can delay physical deletion; do not claim an exact physical-erasure deadline. The clarified policy requires exact access expiry and bounded eventual physical cleanup; the separate account-deletion purge deadline is outside this slice.

### AC8c.6 — fault recovery, restart and durable state

Inject test-owned transient and unexpected failures during capture, a middle continuation, and final-page retrieval using real database work. Failed capture must leave no partial snapshot or cursor-registration side effect; failed continuation must not switch snapshot or advance durable page state. Remove only test-owned faults, then retry the identical valid request/token and compare with the independent expected page. Restart the actual service/process against the same isolated database and verify frozen payload, baseline, token authenticity, deterministic continuation replay and original expiration are preserved, including expired-token classification after payload cleanup. Recheck accepted sync/resource replay and 8a/8b behavior without changing their assertions. Stop only test-created processes.

### AC8c.7 — readable tests and independent oracles

Keep fixtures and expected canonical values explicit and requirement-derived, organize cases by behavior (capture/paging, validation/auth, expiry/cleanup, consistency/recovery), and factor only cohesive setup/assertion helpers. Avoid giant scenario methods, oracle helpers that call production mapping, timing-based races, and tests coupled to incidental SQL/implementation names. Review test diffs for readability and ensure test-only fault hooks are narrowly scoped and cleaned in `finally`.

### AC8c.8 — independent frozen verification

After Worker handoff and Coordinator-approved slots, run the dedicated snapshot tests plus existing pull/pruning, mutation, read, browse and auth regressions, then the full suite, all on separately frozen relevant inputs and under the build lock. Report actual counts, failures and gaps, not historical estimates. This plan does not declare production acceptance.
