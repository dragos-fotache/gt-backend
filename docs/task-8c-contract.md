## Fixed HTTP and snapshot behavior

Implement **GET /v1/sync/snapshot**, returning `200 {records, baselineCursor, hasMore, nextPageToken?}` exactly as OpenAPI SnapshotResult. Each record is a complete canonical SyncUpsertChange, with aggregateType/aggregateId/operation/revision/record agreeing; operation is upsert and revision is positive. No new endpoint or request body schema.

- Allowed query parameters are scalar `pageToken` and `limit`, each at most once. Absent pageToken starts a new snapshot. An explicitly empty token is invalid, never a new start; do not trim opaque token input.
- Limit counts whole records, 1–500, default 200. ASCII decimal digits only, without sign/whitespace/fraction/exponent; out-of-range/overflow/empty/malformed values are `400 invalid_request`. Unknown parameters and duplicate scalar parameters are `400 invalid_request`.
- Continuations bind the **effective numeric limit**. Omitted limit means 200 on every request, not token-inferred size; an omitted continuation limit is valid only if the original effective limit was 200. Equivalent valid decimal spelling does not change numeric context.
- GET body must be absent/zero bytes; a nonempty body is `422 validation_error`. Optional Idempotency-Key has no snapshot replay semantics. Repeating a null-token initial request may create an independent snapshot; only continuation-token replay is promised. No new initial-request idempotency namespace.
- Require a current live service bearer credential on initial pages and continuations. Missing/invalid/expired/revoked access and disabled accounts yield `401 authentication_required`. A different live same-account session may continue its account's snapshot; tokens do not bind login session. New reads after logout/account disablement reject. Already delivered data is not retroactively erased.
- Unknown/malformed/tampered/foreign/context-mismatched tokens are `400 invalid_snapshot_token`, never a silent fresh start. Check authenticity and account/limit context before treating expiry as typed 410: a foreign or changed-limit expired token remains invalid. An authentic, correctly bound expired token is `410 snapshot_expired`, including after expired frozen payload cleanup and restart. No global precedence among independent malformed query/body/auth failures is promised.
- Transient database failures are safe `503 temporarily_unavailable`; unexpected failures are safe `500 internal_error`. No SQL/private IDs/credentials/payloads/stack traces in response or new runner logs. Corrupt/missing required frozen data must fail closed, not masquerade as a complete page or invalid user token.

Do not advance beyond allocated-but-uncommitted publication, combine an old baseline with new roots, or skip commits after the baseline. Persist frozen contents/metadata before exposing a continuation; correctness must survive service restart, not rely on process-local maps, live list keysets or long-lived open transactions. Continuation tokens bind account, snapshot identity, next offset and effective limit. They must be opaque authenticated values, distinguishable from pull and list tokens. Exact full terminal pages have hasMore false; empty snapshots have zero records and a valid nonempty baseline.

At `now >= expiresAt`, reject access. Capture/retry/page access cannot reset expiry; if capture finishes after expiry, do not serve it as valid. Worker must identify the actual creation-time sampling point in its no-edit design.
